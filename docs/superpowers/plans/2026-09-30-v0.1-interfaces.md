## 1. Role key grammar

Agent-derived, needs owner decision (open item from plan 1). Provisional grammar:

- `bigm`
- `clerk-ledger`
- `clanker-<project>`
- `clerk-<project>-<task>`
- `<project>` is `[a-z0-9]+(-[a-z0-9]+)*`. It can contain hyphens.
- `<task>` is `[a-z0-9]+`. It has no hyphen, so the last hyphen of a clerk key separates the project from the task. A ticket `ENG-123` becomes the task `eng123`.
- A key is at most 64 characters.

Go (lane go, `env.go`):

```go
type RoleKey struct {
	Role    string // "bigm", "clanker", "clerk", or "ledger"
	Project string // empty for bigm and ledger
	Task    string // empty except for clerk
}

func ParseRoleKey(s string) (RoleKey, error)
func (k RoleKey) String() string
func (k RoleKey) Parent() string // clerk -> "clanker-<project>"; clanker and ledger -> "bigm"; bigm -> ""
```

Every hierarchy check (lease grant, lease request, role settings write, session launch) uses `ParseRoleKey` and `Parent`, never a string prefix.

## 4. The `deliver` workflow

`/bruh:deliver`, file `plugins/bruh/workflows/deliver.js`, `meta.name` `deliver`.

`args` (JSON object):

```json
{
  "task": "text",
  "acceptance": ["criterion"],
  "base_sha": "40 hex",
  "branch": "name of the task branch",
  "gates": ["go test ./...", "make lint"],
  "test_gates": ["go test ./..."],
  "house_rules": "text of house-rules.md",
  "guides": "text of the guides index of the project, or empty",
  "deliberate": ["choice that reviewers must not flag"],
  "deadline_seconds": 3600,
  "round_cap": 2,
  "answers": {"<id>": "answer text, or a list of answer texts when the question came back; added by the clerk on a relaunch with resumeFromRunId"}
}
```

Result (the return value of the script):

```json
{
  "status": "done | question | findings_left | stopped",
  "branch": "name",
  "base_sha": "sha",
  "head_sha": "sha",
  "tests": {"ran": 0, "passed": 0, "failed": 0, "skipped": 0},
  "findings": [{"file": "path", "line": 1, "summary": "text", "state": "fixed | refuted | open"}],
  "question": {"id": "<id>", "header": "text", "body": "text"},
  "deviations": ["text"]
}
```

`test_gates` is optional and a subset of `gates` (final review M6): the gates that are test suites. Each gate must report a result and exit 0; only a gate of `test_gates` must also run at least one test (`ran > 0`). Without `test_gates`, no gate needs a test count.

A workflow agent with a question calls `question_open`, sends the returned `header` to `main` with `SendMessage`, then calls `answer_wait` with the ID and the deadline. On `pending`, the script returns `status: question`. The clerk relaunches with `resumeFromRunId` and the answer in `args.answers`; the answer goes only into prompts after the question, so earlier agents return cached results.

## 4a. Messages and posts

- Since spec version 0.6, a question ID `<id>` is `Q-<project>-<host>-<n>` and matches `^Q-[a-z0-9]+(-[a-z0-9]+)+-[0-9]+$`. The headers are in spec section 5. In this file, `<id>` is a question ID, except in the `mail/` paths, where it is a message ID. Owner decision 2026-10-03: the form and the host name. Agent-derived, needs owner decision: the normalization and the pattern.
- A start message has the header `START: <subject>` (agent-derived, needs owner decision).
- A reused question ID (spec 5). Owner decision 2026-10-03: a question whose ID bigm already answered, with another subject, is a new question, and bigm tells the asker to open it again. Agent-derived, needs owner decision: the rules below.
  - Only bigm makes this check. It keys each question by the pair of the role key of the asker and the ID.
  - bigm compares the subjects after it removes a trailing space and `(attempt <n>)` (spec 201).
  - The same pair and another subject: bigm sends `ANSWER <id>: reask` with the body "open the question again with a new ID" (spec 203). A clanker and a clerk read the subject `reask` as "open the question again", never as the answer. They open the question again with `question_open`, which gives a new ID.
- When the clanker of a project must act on a watcher event, bigm relays the event to it with the header `DONE: event <project>: <subject>` (spec 533). Agent-derived, needs owner decision.
- A clanker or a clerk sends the notice of a defect of bruh to its parent with the header `DONE: bruh defect: <subject>` (spec section 2, principle 8). Agent-derived, needs owner decision.
- Every post of an agent on a code host ends with the line `<!-- bruh:<role key> -->`. The watcher uses only this marker to tell agent posts from human posts.
- A remote clanker gets its role settings file from `go run -C <plugin root>/mcp . role-settings <role key>`, run on the remote machine.
