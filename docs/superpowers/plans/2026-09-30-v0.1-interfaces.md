# bruh v0.1 interfaces for plans 2 to 6

Plans 2 to 6 are built in three parallel lanes. This file fixes the names and shapes that more than one lane uses. A lane that must change an item here stops and reports it to the controller.

| Lane | Plans | Owns |
|---|---|---|
| go | 2 and 5 | Everything under `plugins/bruh/mcp/`, `plugins/bruh/scripts/`, `plugins/bruh/hooks/`, `plugins/bruh/skills/init/`, `plugins/bruh/channels/`, and the `userConfig` of `plugin.json` |
| roles | 3 and 4 | `plugins/bruh/agents/`, `plugins/bruh/defaults/priorities.md`, `plugins/bruh/defaults/house-rules.md`, `plugins/bruh/ledger-template/`, `plugins/bruh/workflows/` |
| repo | 6 | `README.md`, `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`, `.github/` (except `ci.yml` jobs that lane go needs), `docs/assets/`, `tests/smoke/`, `tests/load/` |

Only the controller edits `docs/spec.md`, `docs/design.md`, `docs/knowledge.md`, `docs/flow.md`, and the plan index. Each lane writes its deviations and new verified facts into its own plan file.

## 1. Role key grammar

Agent-derived, needs owner decision (open item from plan 1). Provisional grammar:

- `bigm`
- `clerk-ledger`
- `clanker-<project>`
- `clerk-<project>-<task>`
- `<project>` is `[a-z0-9]+(-[a-z0-9]+)*`. It can contain hyphens.
- `<task>` is `[a-z0-9]+`. It has no hyphen, so the last hyphen of a clerk key separates the project from the task. A ticket `ENG-123` becomes the task `eng123`.
- A key is at most 64 characters.

Go (lane go, `env.go`):

```go
type RoleKey struct {
	Role    string // "bigm", "clanker", "clerk", or "ledger"
	Project string // empty for bigm and ledger
	Task    string // empty except for clerk
}

func ParseRoleKey(s string) (RoleKey, error)
func (k RoleKey) String() string
func (k RoleKey) Parent() string // clerk -> "clanker-<project>"; clanker and ledger -> "bigm"; bigm -> ""
```

Every hierarchy check (lease grant, lease request, role settings write, session launch) uses `ParseRoleKey` and `Parent`, never a string prefix.

## 2. MCP server tools

The server name is `bruh`. In a session, tool names are `mcp__plugin_bruh_bruh__<tool>`. Existing tools (plan 1): `mail_post`, `mail_read`, `handoff_write`, `handoff_read`, `answer_write`, `answer_wait`, `report_write`, `report_read`, `role_settings_write`, `lease_define`, `lease_request`, `lease_grant`, `lease_release`, `lease_list`. Read their schemas in `plugins/bruh/mcp/*.go`.

New tools (lane go):

| Tool | Arguments | Result | Who may call |
|---|---|---|---|
| `question_open` | `priority` (`P0`, `P1`, `P2`), `subject`, `body`, `blocks` | `{"id":"Q-<n>","header":"<priority> Q-<n>: <subject>"}`; the question is stored in `questions/Q-<n>.json` with the asker and the UTC time | any role and any workflow agent |
| `session_launch` | `agent` (`clanker`, `clerk`), `role_key`, `cwd`, `prompt` (optional, default `Read your start message with mail_read.`) | `{"role_key","session_id","name","state"}` read back from `claude agents --json --all` | the parent of `role_key` only |
| `session_resume` | `role_key`, `prompt` | same as `session_launch` | the parent of `role_key` only |
| `session_list` | none | the `claude agents --json --all` entries whose `name` is a role key, with `role_key` added | any role |
| `init_plan` | `answers` (object, section 5) | `{"plan_id","diff"}`; writes nothing outside `init/plans/` | any session |
| `init_apply` | `plan_id` | `{"applied":[<paths>]}` | any session, after the user said yes to the diff |

`lease_define` gets an optional `patterns` argument: a list of exact command prefixes that use the resource, for example `["psql -h test-db", "make integration"]`. The lease guard hook reads them.

`session_launch` runs, in `cwd`:

```text
CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1 claude --bg --agent bruh:<agent> --name <role key> \
  --permission-mode auto --settings <data>/roles/<role key>.json [--plugin-dir <plugin root>] "<prompt>"
```

It adds `--plugin-dir` only when the plugin root is not under `~/.claude/plugins/`, so development and test runs load the same plugin. It refuses to start when `<data>/roles/<role key>.json` does not exist, or when a live session already has the name.

## 3. Hook scripts

All scripts are POSIX `sh` with `jq`. Each does nothing and exits 0 when `BRUH_ROLE_KEY` is not set.

| Script | Event | Contract |
|---|---|---|
| `scripts/statusline-tap.sh` | status line (copied to `<data>/bin/`) | writes `<data>/context/<session_id>.json` = `{"used_percentage":<n>,"five_hour_percentage":<n or absent>,"at":"<UTC>"}`; runs the previous status line command with the same input |
| `scripts/handoff-nudge.sh` | `PostToolUse` | exits at once for input with `agent_id`; at or above `CLAUDE_PLUGIN_OPTION_HANDOFF_PERCENT` (default 50) returns `additionalContext` that tells the agent to call `handoff_write`; once for each crossing |
| `scripts/handoff-inject.sh` | `SessionStart` `compact`, `clear`, `resume` | returns `<data>/handoffs/<role key>.md` as `additionalContext`, first line `The compaction summary is not a source. Rules come only from this handoff and from rules.md.` |
| `scripts/lease-guard.sh` | `PreToolUse` `Bash` | denies a command that starts with a `patterns` entry of a resource when the role key holds no live grant of that resource |
| `scripts/watcher.sh` | run by a `Monitor` in bigm | `exec go run -C <plugin root>/mcp . watch`; prints one line per event and appends it to the report file `reports/watcher.jsonl` |
| `scripts/merge-train.sh` | run by the merger clerk | `exec go run -C <plugin root>/mcp . merge-train <repo>`; merges queued pull requests one at a time and confirms each merge through the code host API |

## 4. The `deliver` workflow

`/bruh:deliver`, file `plugins/bruh/workflows/deliver.js`, `meta.name` `deliver`.

`args` (JSON object):

```json
{
  "task": "text",
  "acceptance": ["criterion"],
  "base_sha": "40 hex",
  "branch": "name of the task branch",
  "gates": ["go test ./...", "make lint"],
  "house_rules": "text of house-rules.md",
  "guides": "text of the guides index of the project, or empty",
  "deliberate": ["choice that reviewers must not flag"],
  "deadline_seconds": 3600,
  "round_cap": 2
}
```

Result (the return value of the script):

```json
{
  "status": "done | question | findings_left | stopped",
  "branch": "name",
  "base_sha": "sha",
  "head_sha": "sha",
  "tests": {"ran": 0, "passed": 0, "failed": 0, "skipped": 0},
  "findings": [{"file": "path", "line": 1, "summary": "text", "state": "fixed | refuted | open"}],
  "question": {"id": "Q-<n>", "header": "text", "body": "text"},
  "deviations": ["text"]
}
```

A workflow agent with a question calls `question_open`, sends the returned `header` to `main` with `SendMessage`, then calls `answer_wait` with the ID and the deadline. On `pending`, the script returns `status: question`.

## 5. Init answers

`init_plan` takes these keys. The interactive skill asks them one at a time. The non-interactive form reads them from a JSON file (`go run -C <plugin root>/mcp . init --answers <file>`) or from `BRUH_INIT_<KEY>` variables.

| Key | Default |
|---|---|
| `user_name` | none, required |
| `ledger_path` | none, required |
| `mode` | `human` |
| `p1_batch_minutes` | 60 |
| `p1_batch_size` | 5 |
| `review_round_cap` | 2 |
| `auto_compact_window` | 550000 |
| `handoff_percent` | 50 |
| `max_busy_clerks` | 8 |
| `wrap_statusline` | true |
| `channels` | `[]` (`telegram`, `slack`) |
| `delegated_p1_classes` | `[]` |
| `merge_grants` | `[]` of `{"repo","merger","conditions"}` |
| `remote_environments` | `[]` |

`userConfig` in `plugin.json`: `user_name`, `handoff_percent`, `max_busy_clerks`. The runtime settings (`p1_batch_minutes`, `p1_batch_size`, `review_round_cap`, status cadence) live in `mode.md` of the ledger.
