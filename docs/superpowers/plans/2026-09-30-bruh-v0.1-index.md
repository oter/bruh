# bruh v0.1 implementation plans (index)

**Spec:** [../../spec.md](../../spec.md) version 0.4, approved 2026-09-30.

Version 0.1 contains all parts of the specification (owner decision 2026-09-30). The work is split into six plans because the specification covers six subsystems. Each plan produces software that works and is tested on its own. The plans run in this order, because later plans depend on the probe results and the interfaces of earlier plans.

| # | Plan | Delivers | Depends on |
|---|---|---|---|
| 1 | [Foundation and probes](2026-09-30-plan-1-foundation.md) | Repository skeleton, license, CI, the probe results for every "Verify" item that later plans depend on, and the bruh MCP server with all its tools | none |
| 2 | Hooks, status line tap, and init skill | `statusline-tap.sh`, `handoff-nudge.sh`, `handoff-inject.sh`, `lease-guard.sh`, `hooks.json`, `/bruh:init` (interactive and non-interactive) | 1 |
| 3 | Roles and the ledger | `agents/bigm.md`, `agents/clanker.md`, `agents/clerk.md`, the launch procedure, `defaults/priorities.md`, `defaults/house-rules.md`, the ledger template | 1, 2 |
| 4 | The `deliver` workflow | `workflows/deliver.js` with the question path of spec 6.2 | 1, 3 |
| 5 | Loops and integrations | Sweep, watcher, merge train, Orca remote transport, Telegram and Slack channels | 1 to 4 |
| 6 | Verification and release | Load test, smoke test, README install guide, day-0 maturity items, `v0.1.0` release | 1 to 5 |

Plans 2 to 6 are written when the plan before them is done, so that each plan uses the real probe results and the real interfaces instead of guesses.

## Deviations from the specification (for owner review)

1. Tests use `go test` instead of `bats`. Go is already required for the MCP server (owner decision 2026-09-30: Go, started with `go run`), so no new tool is necessary. Plan 2 tests the shell scripts from Go tests. CI still runs `shellcheck`.
2. The MCP server has four tools more than spec section 10.1 lists: `report_read` (bigm reads report files through the server, not by path), `lease_define` (bigm defines a shared resource and its capacity), `lease_list` (a grantor sees requests and grants), and a lock around the lease state, because several sessions write it.
